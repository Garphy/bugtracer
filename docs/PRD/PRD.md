## 1. 产品概述与背景

### 1.1 产品定位
**BugTracer 2.0** 是一套轻量级、高密度交互、全快捷键驱动的缺陷跟踪与需求管理系统。它既是研发团队（开发、测试、管理者）高效流转缺陷的日常工作台，也是 AI 研发智能体（LLM Coding Agents，如 Cursor / Claude / Antigravity）直接协同人机开发的配套支撑软件。

### 1.2 核心设计哲学
1. **极低交互阻力 (Zero-Friction UX)**：
   - **35px 极高密度列表**：一屏容纳数十条 Bug，拒绝现代系统冗余的大留白。
   - **1 秒状态流转 (Flagger & Tick Action)**：
     - 鼠标悬浮/点击 Bug ID 时，前缀 `#` 自动平滑切换为 `▼` 下拉图标，点击弹出状态流转浮层；
     - 鼠标悬浮在活动缺陷状态 Badge 上时，动态展示 `✓ 解决` 提示，支持 1 键快速流转。
   - **全键盘快捷键覆盖**：`Ctrl + \`` 新建、`Ctrl + Enter` 提交、`Esc` 关闭、`< 上一条` / `下一条 >` 连续评审。
   - **零步骤贴图**：剪贴板截图按 `Ctrl + V` 直接粘贴自动上传，支持文件拖拽上传。
   - **Markdown 与图文智能混排**：全面集成标准 Markdown 解析引擎，正文中支持直接输入 `图1`、`图2` 或 Markdown 图片 `![图1](...)`，自动映射内嵌对应附件截图并支持实时预览。
   - **一键列表导出**：支持一键将当前页所有缺陷提取为整洁的无格式文本并复制到系统剪贴板。
2. **轻量与弹性双数据库引擎**：
   - **默认 SQLite**：单文件存储，零配置，解压即用。
   - **无缝切换 MySQL / MariaDB**：仅需修改环境变量连接串，满足团队上云与多节点扩展。
3. **单端口一体化部署**：
   - 后端 FastAPI 自动化托管 Vue 3 编译产物，单命令 `python run.py` 或单容器完成全栈交付（默认端口 `5002`）。
4. **原生 AI Agent 赋能 (Model Context Protocol)**：
   - 原生内置 MCP Server（支持 STDIO 与 SSE 两种通信协议），提供标准结构化工具集，让大模型在辅助编程时能够读取上下文、自动检索 Bug、提交缺陷、追加技术讨论与修改状态。

## 2. 用户角色与权限控制矩阵

系统内置 4 类系统角色，具备明确的职责与状态流转约束。

### 2.1 角色定义
* **系统管理员 (Admin)**：拥有系统最高权限，负责项目增删改、模块配置、人员管理与全状态流转。
* **技术开发 (Coder)**：负责缺陷修复与技术跟进，重点在于将缺陷标记为已解决、部分处理或不处理。
* **测试质量 (Tester)**：负责缺陷提交、验收、关闭及重新激活。
* **访客用户 (Guest)**：只读权限，可查看项目缺陷列表与报告。

### 2.2 缺陷状态定义
系统定义 8 种标准化缺陷状态：

| 状态 ID | 状态代码 | 状态名称 | 颜色标识 | 说明 |
| :---: | :---: | :---: | :---: | :--- |
| **0** | `closed` | 已关闭 | 灰色 (Gray) | 缺陷已验证通过或终结 |
| **1** | `new` | 新增 | 蓝色 (Blue) | 新提交的未处理缺陷 |
| **2** | `key` | 重要/高优 | 红色 (Red) | 需加急/高优先级处理的缺陷 |
| **3** | `part_fixed` | 部分处理 | 橙色 (Amber) | 已完成部分修复，需进一步跟进 |
| **4** | `fixed` | 已解决 | 绿色 (Green) | 开发已修复，等待测试验证 |
| **5** | `wont_fix` | 不处理 | 浅灰 (Slate) | 经评估不予修复或非缺陷 |
| **6** | `todo` | 待办 | 紫色 (Purple) | 待排期或延期处理的任务 |
| **7** | `idea` | 备忘 | 青色 (Teal) | 灵感、备忘或需求构想 |

### 2.3 状态流转与操作权限约束矩阵

| 目标状态 | 管理员 (Admin) | 技术开发 (Coder) | 测试人员 (Tester) | 访客 (Guest) |
| :--- | :---: | :---: | :---: | :---: |
| **0: closed (已关闭)** | ✅ 允许 | ❌ **禁止直接关闭**（需测试/管理员验收） | ✅ 允许（验证通过后关闭） | ❌ 禁止 |
| **1: new (新增/激活)** | ✅ 允许 | ❌ 禁止 | ✅ 允许（未修复重新激活） | ❌ 禁止 |
| **2: key (标为重要)** | ✅ 允许 | ❌ 禁止 | ✅ 允许 | ❌ 禁止 |
| **3: part_fixed (部分处理)** | ✅ 允许 | ✅ 允许 | ❌ 禁止 | ❌ 禁止 |
| **4: fixed (已解决)** | ✅ 允许 | ✅ **允许（主要流转目标）** | ✅ 允许 | ❌ 禁止 |
| **5: wont_fix (不处理)** | ✅ 允许 | ✅ 允许 | ✅ 允许 | ❌ 禁止 |
| **6: todo (待办)** | ✅ 允许 | ❌ 禁止 | ✅ 允许 | ❌ 禁止 |
| **7: idea (备忘)** | ✅ 允许 | ❌ 禁止 | ✅ 允许 | ❌ 禁止 |
| **列表行状态徽章 1 键快捷流转** | ✅ 允许 (new->fixed, fixed->closed) | ✅ 允许 (new->fixed; 拦截 fixed->closed) | ✅ 允许 (new->fixed, fixed->closed) | ❌ 禁止 |

## 3. 功能需求规格说明

### 3.1 缺陷工作台主页 (MainView)
* **顶栏导航**：
  * 显示当前登录人员姓名、账号及角色 Badge。
  * 个人设置与 MCP API Key 查看/重置入口。
  * 【管理模式 / Debug 模式】一键切换（仅管理员可用）：
    * 管理模式：查看全量项目人员缺陷。
    * Debug 模式：仅过滤出指派给自己或由自己提交的缺陷。
  * 项目下拉选择器：展示各项目及对应的**未解决活动缺陷数量**（`active_bugs_count`）。
  * 导航快捷跳转：`[项目报表]`、`[管理后台]`。
* **模块分类 Tab 栏**：
  * 支持 `[全部模块]` 及各子模块 Tab。
  * 每个模块 Tab 标明该模块下的 Bug 数量。
  * `[+ 提交新Bug]` 按钮（附带快捷键提示 `Ctrl + \``）。
  * `[📋 复制列表]` 按钮：一键提取当前页所有 Bug，格式化为无样式纯文本复制到剪贴板。
* **状态过滤栏 (FilterBar)**：
  * 8 个状态复选框。默认选中 `[1:新增, 2:重要, 3:部分处理]`。
  * **双击单选特性**：在任意状态复选框上双击，立即只勾选该单项状态。
  * `[全选]` / `[反选]` / `[常用 (1/2/3)]` 快速选择按钮。
  * 智能搜索输入框 (SearchBar) 与语法帮助弹层。
* **35px 高密度缺陷列表**：
  * **Bug ID 列**：设置 `min-w-[46px]` 等宽对齐；鼠标悬浮时 `#` 自动切换为 `▼` 图标提示，点击弹出 FlaggerPopover 状态流转浮层。
  * **状态 Badge 列**：采用去边框淡彩现代设计；设置固定 `w-[64px]` 宽度；鼠标悬浮展示 `✓ 解决` / `✓ 关闭` 动态操作提示，点击触发一键流转。
  * **内容摘要**：
    * 标题左侧严格水平对齐。
    * 展示 `『模块名』` 前缀。
    * 解析 `[b]红字加粗[/b]` 重点标出。
    * 自动识别 URL 外链化。
  * **右侧元数据**：附件图标 (`📎`)、版本号 (`v1.0.0`)、指派处理人、最后更新时间。
  * **双击行操作**：双击任意行弹出 Bug 详情/编辑对话框。
  * **行样式反馈**：指派给当前用户的缺陷左侧展示亮蓝色指示条；已关闭/不处理缺陷整体半透明。
* **空状态智能引导**：
  * 当当前状态过滤条件下无数据时，展示友好引导并提供 `【全选状态】` 一键跳转按钮。
* **分页控制器**：
  * 高度紧凑的分页条，支持上一页、下一页及总条数显示。
* **底部快捷键提示栏**：
  * 常驻底部，提示全键盘快捷操作方式。

### 3.2 缺陷详情、提单与编辑系统 (BugDialog)
* **三合一弹窗设计**：
  * 新建缺陷模式、查看缺陷模式、编辑缺陷模式统一在轻量浮层中完成。
* **连审翻页功能**：
  * 弹窗右上角提供 `< 上一条` / `下一条 >` 按钮，无需关闭弹窗即可连续审阅列表中的缺陷。
* **快捷提单与编辑表单**：
  * **所属模块**：下拉选择。
  * **版本号**：文本输入（自动带出项目的默认版本号）。
  * **指派处理人**：下拉选择（仅列出已分配到当前项目的成员）。
  * **缺陷状态**：根据当前用户角色动态过滤可选状态。
  * **缺陷描述 (Content)**：
    * 完整集成 `marked` 标准 Markdown 语法（标题、代码块、引用、列表、表格）。
    * 向下兼容老版本 `[b]加粗红字[/b]` 语法。
    * **`Ctrl + V` 剪贴板截图直接粘贴**：监听粘贴事件，若为图片则自动上传并生成附件记录。
    * **文件拖拽上传**：支持将外部文件直接拖拽进入弹窗区域完成上传。
    * **图文混排与附件自动映射**：支持正文中输入 `图1`、`图2` 或 `![图1](...)`，自动内嵌对应附件缩略图并支持点击查看全尺寸大图；底部展示未引用的附件图集。
    * **实时预览切换**：支持在提单/编辑时一键切换 `[实时预览 Markdown / 切换编辑]`。
* **技术讨论与操作审计流 (CommentTimeline)**：
  * 支持追加技术分析评论（开发排查结论、复现过程、修复推演等）。
  * 完整审计追踪：谁在何时将状态由 A 改为 B、修改了描述、上传了附件等。

### 3.3 快捷搜索语法解析系统 (SearchParser)

系统支持在搜索框中直接输入快捷语法完成精准多维过滤：

| 语法格式 | 示例 | 检索逻辑 |
| :--- | :--- | :--- |
| `[id]` | `102` | 精确匹配 Bug ID 为 102 的缺陷（单 ID 自动打开详情） |
| `[id1,id2,...]` | `102,105,108` | 批量检索多个指定 ID 的缺陷列表 |
| `(用户ID)` | `(1)` 或 `(admin)` | 检索创建者（提出人）为指定用户的缺陷 |
| `{用户ID}` | `{2}` 或 `{coder1}` | 检索指派给指定用户的缺陷 |
| `!{用户ID}` | `!{2}` | 检索非指派给指定用户的缺陷 |
| `{日期1~日期2}` | `{2026-08-01~2026-08-21}` | 检索最后变更时间在指定起止日期区间的缺陷 |
| `关键词` | `登录超时` | 模糊匹配缺陷描述、标题及版本号 |
| `复合语法` | `{2} 登录超时` | 检索指派给用户 2 且描述中包含“登录超时”的缺陷 |

### 3.4 MCP (Model Context Protocol) 协议与 AI 协同规范

系统作为标准 MCP Server，提供以下 8 个对外标准工具：

1. `list_projects()`：获取所有项目列表及活动缺陷总览。
2. `get_project_context(project_id: int)`：获取指定项目的模块结构、成员列表及上下文。
3. `query_bugs(project_id: int, status_filter, module_id, search, page, page_size)`：支持全部快捷语法的缺陷检索。
4. `get_bug_detail(bug_id: int)`：获取缺陷元数据、附件、讨论评论与修改审计历史。
5. `create_bug(project_id, content, module_id, ver, assignee_id, priority, status)`：AI 智能体直接提交缺陷或开发任务。
6. `update_bug_status(bug_id, status, close_reason)`：流转缺陷状态（如标记为 fixed 或 closed）。
7. `add_bug_comment(bug_id, comment)`：为缺陷追加技术方案、排查推演或代码修复记录。
8. `get_project_stats(project_id)`：获取全项目质量 KPI 与人员负荷报表。
